# Max 奶油绒团小狗与房间交互设计

## 背景

当前 Max 的小狗已经从单张图片改成了可分层、可动的线稿 SVG，但现有轮廓仍然偏几何，第一眼不够像一只自然的小狗。用户希望它更接近短视频中“奶油白、头大身小、软糯、会做出明显动作”的可爱角色气质，同时明确要求角色仍然是狗，而不是泛化宠物或抽象吉祥物。

参考视频只用于理解整体的角色语言和动势，不复制其中的角色、镜头、文字、场景、素材或具体动作编排：[视频页面](https://www.douyin.com/video/7686789114254937379)。Max 需要是一只原创、可识别、能长期陪伴用户的线条小狗。

本规格取代之前以西瓜和较硬线稿为中心的角色设计；房间、聊天、记忆和数据边界继续沿用现有实现。

## 目标

把 Max 设计成“奶油绒团小狗”：

- 第一眼明确是狗：大圆头、短口鼻、两只下垂耳、紧凑身体、四只可见的小爪、短卷尾。
- 保留线条插画的识别度，但让线条和形体更柔软，避免像拼接出来的几何图形。
- 角色重心放在房间左侧的生活场景中，大小、姿态和装饰保持足够留白，不遮挡聊天区域。
- 让 Max 的状态能被看见：待机有呼吸和小幅重心变化，思考有偏头和不对称耳朵，回复时有短促的身体和四肢回应。
- 角色能长期扩展动作和表情，而不用重新换一张整图。

## 非目标与边界

- 不改变登录、聊天、记忆、主动消息、Supabase、Render 或 API 数据结构。
- 不把视频中的角色直接临摹，也不运行时加载视频、远程图片或第三方角色资源。
- 不再使用头像图中的西瓜作为角色识别元素；角色的水果、贴纸和背景装饰不参与身份识别。
- 不新增网络请求。角色和房间装饰随桌面端构建，离线打开时也能正常显示。
- 保留当前 `RoomActivity` 的 `idle`、`thinking`、`speaking` 三种状态以及现有聊天行为；本次只让这些状态驱动更清楚的视觉反馈。
- 保留小狗的可访问语义：根 SVG 使用 `role="img"`，可访问名称继续为 `Max，线条小狗`，装饰层使用 `aria-hidden`。
- `prefers-reduced-motion` 下保持完整静态画面，不依赖动画才能辨认角色或使用聊天。

## 视觉方向

### 轮廓

采用略微三分之四朝向用户的原创姿态，不使用僵硬的侧面剪影：

- 头部明显大于身体，脸部是最先被看到的识别区域。
- 两只耳朵从头部两侧自然下垂，左右高度和摆幅允许有细微差异。
- 口鼻是短而圆的独立区域，鼻子用深色小椭圆表示；嘴线简洁，不画复杂拟人嘴型。
- 身体是小而饱满的椭圆团，四条腿从身体下方分开，四只爪子都能看到落在地面或地毯上。
- 尾巴从身体后侧伸出，末端微卷，静止时也能看出是尾巴，不与后腿混在一起。
- 不依靠水果、帽子或文字才能判断是狗；项圈、脸颊小色块等只作为辅助个性。

### 线条与色彩

- 轮廓使用圆角、粗细稳定的深色线条；内部细节减少，避免目前“零件拼接”的硬边感。
- 主体使用奶油白，阴影用很浅的暖灰或米色，和房间的浅青、珊瑚色形成柔和对比。
- 鼻子、眼睛和爪缝使用深墨色；脸颊、舌头或项圈可以使用当前的珊瑚色作为小面积强调。
- 不新增大面积高饱和背景，不让角色与房间装饰争夺视觉中心。
- 所有颜色继续优先复用现有 CSS 变量，避免在组件里散落不可维护的颜色常量。

## 动作设计

动作要有“活着”的感觉，但不能持续抖动到影响阅读。

### idle

- 身体以很慢的节奏上下呼吸，头部与身体略有不同步。
- 尾巴缓慢左右摆动，偶尔停顿后再继续。
- 耳朵不同时轻抖一次，眼睛间歇性眨眼。
- 四条腿保持可辨认的落地关系，只做轻微的交替重心变化；不让爪子漂浮或穿过地面。
- 窗光、尘埃、植物和蒸汽继续使用低幅度环境动效，和小狗动作错开节奏。

### thinking

- 头部向一侧轻轻倾斜，左右耳形成明显但自然的不对称。
- 一只前爪向胸口或脸颊附近靠近，另一只前爪保持支撑；后腿不离地。
- 尾巴动作放慢，眼睛和口鼻保持安静，传达“在想”而非“在说话”。

### speaking

- 开始回复时身体有一次短促的前倾/回弹，随后回到缓慢呼吸。
- 嘴部或舌头有轻微开合，耳朵和前爪各有一次小回应，不做连续夸张弹跳。
- 如果聊天请求失败，角色不表现成开心状态；保持安静姿态，由聊天区显示错误信息。

### 动画约束

- 每个动作都通过已有的活动状态 class 控制，动画逻辑不放进聊天组件。
- 不能用随机定时器制造不可测试的状态；需要随机感时使用 CSS 延迟或已有状态驱动的稳定节奏。
- `prefers-reduced-motion: reduce` 时停用位移、旋转、闪烁和视差，仅保留静态姿态与颜色。

## 组件与数据契约

`MaxDogSprite` 继续输出一个内联 SVG 根节点，不增加运行时资源请求。现有稳定选择器必须保留，方便测试和后续扩展：

- `dog-body`
- `dog-head`
- `dog-tail`
- `dog-ear-left`、`dog-ear-right`
- 四条腿和四只爪子的现有 `data-testid`
- `dog-muzzle`、`dog-nose`、`dog-collar`

如果为了让轮廓更清楚需要增加眼睛、脸颊或舌头节点，应只新增稳定的、语义清晰的 `data-testid`，不改动聊天 API 或持久化字段。根节点继续保留 `max-dog` 与活动状态 class，并让四肢、耳朵、尾巴、嘴部各自拥有可独立控制的 class。

`MaxRoom` 继续负责房间背景和环境层：窗户、墙面层次、植物、架子、桌面物件、地毯、便签、尘埃和蒸汽都属于场景装饰，统一标记为 `aria-hidden`。小狗仍是场景中唯一需要被辅助技术识别的视觉主体。

## 验收标准

### 用户可见

1. 不看说明文字，只看左侧画面也能在第一眼认出是一只白色小狗。
2. 头、耳朵、短口鼻、四只爪和卷尾的关系清楚；不出现像兔子、团子、拼接玩偶或无头身体的误读。
3. 不再出现西瓜或头像裁切造成的角色残留；背景装饰不抢过小狗。
4. 待机、思考、回复三种状态的差别能看见，但动画不会让人分心或晕眩。
5. 小狗在窗口缩放时仍保持完整，不被房间边界、聊天面板或滚动条裁掉。

### 工程与回归

1. 组件测试覆盖根节点可访问名称、稳定 `data-testid`、四肢完整性和三种活动状态 class。
2. 桌面端现有测试、lint、typecheck、build 和 `verify:secrets` 全部通过。
3. Windows 打包产物能启动，且产物中包含内联 SVG 和对应动画 class，不依赖外部图片 URL。
4. 安装后的 Max 在登录后仍能打开聊天，记忆和主动消息链路不受影响；本次不把“角色更换完成”误报成后端或登录功能修复。
5. 在开启减少动画设置后，画面仍然完整可读，聊天输入和发送按钮仍可用。

## 实施顺序（规格通过后）

1. 先更新 `MaxDogSprite` 的 SVG 分层结构，确保四肢、耳朵、尾巴和口鼻都是真实可见的狗形体。
2. 再更新 Max 相关 CSS 动画和减少动画分支，保留现有活动状态接口。
3. 调整房间装饰的层级、对比度和留白，确保背景为角色服务。
4. 补齐/更新组件测试，运行桌面端测试、lint、typecheck、build 与密钥检查。
5. 打包并安装，启动已安装程序做一次可见验收，再根据实际截图微调比例和动作幅度。
